resources/viewer.html runs the browser scene. Three.js provides rendering, OrbitControls provides navigation, URDFLoader builds the link/joint model, and STLLoader/ColladaLoader read mesh formats. VisualizationPanel serves these resources and package meshes over an ephemeral loopback HTTP port. Its path resolver confines requests to configured roots. Updating that code requires preserving both the resource mapping and path boundary.

For GUI task serialization, start with open_task_form() to select the dialog. On Save, BaseTaskForm._on_save() calls the form’s collect_values() method and stores the edited task dictionary in dialog.result. The task parser is the receiving contract; form fields and parser defaults must agree.

Models, tools and teaching packages

The four CMS/LIX description and MoveIt packages own models, planning configuration and bringup. CMS additionally compiles cms_servo_node, the C++ Servo implementation used by optional joystick control. Three local end-effector packages supply the ePick overlay and OnRobot model/driver; hardware explains them.

hello_orchestrator_py is a separate teaching example with print, move and orchestrator servers plus matching stages and a JSON client. Its companion interface package defines PrintMessage, MoveToNamedState and OrchestratorTask. The demo uses {"type": "move"} rather than the main application’s task_type schema. It requires a configured MoveIt planning group and named state; its move example can execute motion.
