Setup and deployment

Beamline configuration, launch descriptions, tool-specific MoveIt startup, and process cleanup. Docker helpers build and publish images.

Read the guide · All subsystems · Symbol index

Start here

  • load_beamline_config — Find how the active beamline YAML is selected, parsed, and cached for launch and runtime consumers.

  • generate_launch_description — Check which action servers start by default and how optional vision, pipettor, and tracing components are enabled.

  • MoveItLifecycleManager.launch_moveit_with_gripper — Trace payload checks, model selection, launch attempts, and readiness checks when the robot stack starts or changes tools.

Modules

Module

Responsibility

Entries

Beamline configuration

Load and validate the selected beamline YAML, cache its shared mapping, resolve resource paths, and translate settings for ROS launch consumers.

18

MoveIt lifecycle

Start, reuse, and replace MoveIt for the selected gripper. Readiness covers action availability, scene loading, and nonempty robot descriptions; real-hardware startup also checks control and joint feedback and applies the payload.

21

EROBS application launch

Launch EROBS action servers and the orchestrator, with optional vision, pipettor, joystick, and tracing support.

1

CMS robot and MoveIt launch

CMS gripper-parameterized UR driver/MoveIt launch for none, epick, hande, 2fg7 or pipettor, sourcing per-gripper values from beamline YAML. Includes OMPL/Pilz/STOMP and optional joystick Servo. Uses the UR driver’s robot_state_publisher rather than creating another; payload setting is delegated to lifecycle management.

2

LiX robot and MoveIt launch

LiX UR5e/Hand-E launch with OMPL and Pilz pipelines, RViz, controller overlay and a delayed hard-coded payload service call. No configurable gripper, camera or tool-exchange branch.

2

MCP startup with recording

Starts rosbridge, Beambot, and a selected-topic bag recorder. Beambot output also goes to a log file.

1

MCP startup without recording

Starts rosbridge and Beambot, with Beambot output copied to a log file. It does not start a bag recorder.

1

Mock-hardware MCP startup

Starts rosbridge, Beambot with mock UR hardware, and a selected-topic bag recorder. Other devices remain separately configured.

1

Docker image build and publish

Build Docker images and push their latest tags to GHCR. These functions publish images as well as building them.
