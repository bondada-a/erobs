CMS Servo controller

Run the CMS MoveIt Servo node. It accepts joint-jog, twist, or pose commands and publishes controller commands and status.

These functions require a live ROS/MoveIt stack and can command robot motion.

src/custom-ur-descriptions/cms_moveit_config/src/servo_node_jazzy.cpp · Source

Motion planning · Guide · Symbol index

How it is used

CMS bringup uses this local MoveIt Servo executable for continuous joint, twist, or pose commands. Clients publish commands or use the pause and command-type services; they do not call its C++ callbacks directly.

main() creates the wrapper and spins its ROS node. The constructor starts servoLoop() on a worker thread; subscription callbacks retain incoming commands for that loop. Follow the loop when investigating stale commands, pauses, or controller output.

Meaning

Number of process command-line arguments.

Argument strings passed to rclcpp::init().

ServoNode

Owns the ROS node, planning-scene monitor, Servo instance, and control-loop thread. ROS callbacks update its inputs; the worker computes and publishes controller commands. Destruction requests the worker to stop and joins it.

ServoNode::servoLoop()

Run the timed control loop, select the pending command type, compute the next state, and publish accepted output and status.

Internal helper · Source

void ServoNode::servoLoop()

Returns: void when ROS stops or stop_servo_ becomes true.

Errors: INVALID and HALT_FOR_COLLISION states prevent command publication. Pending messages for an unexpected command type are cleared with a warning. No outer exception handler is installed.

Side effects: Waits for the initial robot state, updates smoothing and the command window, and publishes JointTrajectory or Float64MultiArray output plus ServoStatus. While paused it resets smoothing and sleeps.

Used by: The worker thread started by ServoNode().

ServoNode::pauseServo()

Pause or resume Servo processing and report the resulting state.

Callback · Source

void ServoNode::pauseServo(const std::shared_ptr<std_srvs::srv::SetBool::Request>& request,
                           const std::shared_ptr<std_srvs::srv::SetBool::Response>& response)

Parameter

Meaning

request

SetBool request: data=true pauses; data=false resumes.

response

Response object populated with success and a human-readable state message.

Returns: void; writes response.success and response.message. An already active pause state is reported as success.

Errors: Underlying state reads and Servo operations are not caught locally. Resuming requests a blocking current-state read.

Side effects: Pausing disables collision checking. Resuming refreshes the current robot state, resets smoothing, clears the output rolling window, and restores collision checking. Pending input messages and their new-message flags are retained. Shared pause state changes under the mutex.

Used by: The ~/pause_servo service callback.

ServoNode::switchCommandType()

Select a valid Servo command enum and report whether the resulting mode equals the request.

Callback · Source

void ServoNode::switchCommandType(const std::shared_ptr<moveit_msgs::srv::ServoCommandType::Request>& request,
                                  const std::shared_ptr<moveit_msgs::srv::ServoCommandType::Response>& response)

Parameter

Meaning

request

ServoCommandType request with command_type between CommandType::MIN and MAX.

response

Response object whose success field records whether the requested mode became active.

Returns: void; result is written to response.success.

Errors: Out-of-range values log a warning and do not call setCommandType(). No exception recovery is provided.

Side effects: May change which input command type servoLoop() accepts.

Used by: The ~/switch_command_type service callback.

ServoNode::~ServoNode()

Request that the servo loop stop, then join its worker thread if it is joinable.

Lifecycle · Source

ServoNode::~ServoNode()

Returns: Destructor; no returned value.

Errors: No local recovery around thread joining.

Side effects: Sets stop_servo_ and blocks until the worker thread exits.

Used by: Object destruction after the owning shared pointer is released.

ServoNode::ServoNode()

Create the ROS node, planning-scene monitor, Servo instance, command subscriptions, output publishers, control services, and worker thread.

Lifecycle · Source

ServoNode::ServoNode(const rclcpp::NodeOptions& options)

Parameter

Meaning

options

ROS node options passed to the underlying node named servo_node.

Returns: Constructs a ServoNode instance.

Errors: Failure to obtain FIFO scheduling or a realtime kernel logs a warning and continues. ROS, parameter, planning-scene, and thread construction errors are not caught here.

Side effects: Creates ROS entities, attempts realtime scheduling, and starts servoLoop() on a separate thread. The active Servo stack can publish motion commands.

Used by: main() constructs the node before spinning the executor.

ServoNode::processJointJogCommand()

Convert a fresh joint-jog command into the next Servo state, or request a smooth halt for stale input.

Internal helper · Source

std::optional<KinematicState> ServoNode::processJointJogCommand(const moveit::core::RobotStatePtr& robot_state)

Parameter

Meaning

robot_state

MoveIt robot state used as the starting state for the next Servo calculation.

Returns: An optional KinematicState. Fresh input returns the Servo result; stale input returns a halt state only while smoothHalt() reports that stopping is still in progress.

Errors: Displacements are warned about and cleared; they are not executed. INVALID Servo status clears new_joint_jog_msg_. Staleness uses incoming_command_timeout. Exceptions from Servo or timestamp operations are not caught.

Side effects: Clears pending flags for the other command types and updates the active command flag. It computes a state; publication happens in servoLoop().

Used by: servoLoop(), after it checks the selected command type.
