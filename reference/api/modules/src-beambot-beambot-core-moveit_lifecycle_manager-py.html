MoveIt lifecycle

Start, reuse, and replace MoveIt for the selected gripper. Readiness covers action availability, scene loading, and nonempty robot descriptions; real-hardware startup also checks control and joint feedback and applies the payload.

beambot.core.moveit_lifecycle_manager · Source

Setup and deployment · Guide · Symbol index

How it is used

The orchestrator and tool-exchange manager use launch_moveit_with_gripper() to reuse a matching live process or launch the requested model. Real-hardware launches can change tool voltage, restart external control, and set the payload. Payload and voltage values are validated when the beamline configuration loads.

model_revision identifies the gripper and, where configured, its cup profile. The same configuration keeps the same identity across launches; it is not a content hash. Runtime model checks require nonempty URDF/SRDF strings from /move_group. Tool links, groups, states, and collision geometry are checked separately by the offline model tests.

MoveItLifecycleManager.launch_moveit_with_gripper()

Reuse a live process with the requested tool/cup revision, or relaunch and publish nonempty robot descriptions. A failed real-hardware attempt is stopped and retried once; mock mode makes one attempt.

Lifecycle · Source

launch_moveit_with_gripper(self, gripper: str) -> bool

Parameter

Meaning

gripper

Configured tool name. cup_override takes precedence over cup_profile only for grippers whose configuration defines that field.

Returns: True when reuse or startup succeeds, otherwise False.

Errors: Unknown gripper raises KeyError; unhandled helper errors propagate. A failed final launch is not automatically killed here.

Side effects: May kill/relaunch processes, configure hardware, load scenes and publish model descriptions. Success assigns the stable prefix + gripper [+ __cup] revision; restarting the same configuration does not create a new identity.

Method · Source

Returns: Arm positions in radians, or None until every configured joint has a value. Mock mode normally returns None because this manager has no joint-state subscription.

MoveItLifecycleManager.kill_current_process()

Stop the MoveIt launch session: send SIGTERM to its process group, wait up to 3 s for every member to exit, then SIGKILL the group. Clear model identity and optionally drain execute_trajectory discovery.

Lifecycle · Source

kill_current_process(self, drain: bool=True)

Parameter

Meaning

drain

When true (default), wait for /execute_trajectory to leave discovery before returning, so the next launch is not mistaken for ready. Shutdown passes false because no launch follows.

Returns: None.

Errors: ProcessLookupError from signalling is suppressed; other signalling, wait or discovery errors propagate.

Side effects: Clears the model revision first. The launch was started in its own session, so its PID is the process-group ID. Polls every 50 ms until no group member remains, sends SIGKILL to the group after 3 s, waits for the launch parent and logs the stop time. Processes that start their own session are outside this group. With drain, waits up to 10 s for DDS graph cleanup; timeout only warns. Cached voltage is retained.

MoveItLifecycleManager._attempt_launch()

Set changed real tool voltage and wait for power-up, spawn robot bringup in its own process session, wait for MoveIt and load obstacles. On hardware, also restart external control, verify joints, and set the payload. Configuration validation occurs before this method.

Internal helper · Source

_attempt_launch(self, gripper: str, cup_profile: str) -> bool

Parameter

Meaning

gripper

Configured gripper name.

cup_profile

Resolved cup-profile override forwarded only when nonempty.

Returns: True when all applicable readiness gates succeed; False at the first handled failure.

Errors: Process-spawn exceptions are caught. Gripper/config conversion and some helper exceptions propagate. Failure after spawning leaves cleanup to the caller.

Side effects: May send voltage commands, sleep 2 s, spawn ros2 launch, apply collision scene, restart robot control and set physical payload.

Send a set_tool_voltage URScript command to the robot secondary interface at TCP port 30002. Allowed values are validated when the beamline configuration loads.

Internal helper · Source

_set_tool_voltage(self, voltage: int) -> bool

Parameter

voltage

Previously validated tool supply setting: 0, 12 or 24 volts. This helper formats it with int() and does not recheck the allowed set.

Returns: True after bytes are sent; False for missing robot IP or a caught socket/conversion/send failure. No controller acknowledgement is read.
