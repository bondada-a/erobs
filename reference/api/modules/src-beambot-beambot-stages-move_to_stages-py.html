MoveTo planning stages

Compose and execute named, relative and Cartesian MoveTo goals, using shared validation, target-specific fallback planners and TF-based tool-tip selection.

beambot.stages.move_to_stages · Source

Motion planning · Guide · Symbol index

How it is used

MoveToActionServer uses run() to plan and execute one goal. The orchestrator instead uses add_to_task() to compose multiple moves into a batch. Both paths share target validation, planner selection, and tool-tip resolution.

Read add_to_task() for the differences between named, relative, and Cartesian targets. Temporary instances own TF subscriptions and should be released with close() after batch execution.

Callable

MoveToStages.add_to_task

Validate a MoveTo goal and append target-specific stages. Automatic relative moves use LIN/Cartesian/PTP; named joints/states use PTP then the configured general pipeline; Cartesian goals prefer seeded IK/PTP then LIN/Cartesian. XYZ-only targets use roll 180°, pitch 0° and live tip yaw.

Unregister this instance’s TF listener subscriptions.

MoveToStages

BaseStages subclass that converts MoveToAction fields into motion stages. It owns a TF listener for tool-frame selection and current orientation, and exposes separate composition and execution paths.

Inherits from: BaseStages.

MoveToStages.run()

Create a fresh MoveTo task, append the goal’s stages, then plan and execute it.

Entry point · Source

run(self, goal) -> str | None

Parameter

Meaning

goal

MoveTo action goal consumed by add_to_task.

Returns: None on completion or an error string from stage construction/planning/execution.

Errors: Unhandled construction/JSON errors propagate to the action-server boundary.

Side effects: Creates/plans a task and commands robot motion.

MoveToStages.add_to_task()

Validate a MoveTo goal and append target-specific stages. Automatic relative moves use LIN/Cartesian/PTP; named joints/states use PTP then the configured general pipeline; Cartesian goals prefer seeded IK/PTP then LIN/Cartesian. XYZ-only targets use roll 180°, pitch 0° and live tip yaw.

Method · Source

add_to_task(self, task: core.Task, goal, planner=None) -> str | None

Parameter

Meaning

task

MTC task receiving stages.

goal

MoveTo action goal: named target with poses_json, direction/distance in metres, or XYZ metres plus optional RPY degrees; planning_type and constraints_json select planning behavior.

planner

Optional explicit planner overriding automatic selection.

Returns: None when stages were appended; validation/pose error string otherwise.

Errors: Invalid motion selection becomes an error string; malformed constraints JSON/data and MTC/TF/helper errors can propagate.

Side effects: Appends stages, resets/sets endpoint pinning, queries TF/IK for Cartesian goals and populates planner caches; does not execute the task.

Parameter
