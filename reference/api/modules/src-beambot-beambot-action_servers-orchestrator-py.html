Task orchestrator

Validate task scripts and coordinate tool setup, motion batches, child actions, cached replay, pause, and cancellation.

Only a goal containing one batch is eligible for trajectory replay. Pause and cancellation are checked at execution boundaries. Vacuum monitoring is disabled.

beambot.action_servers.orchestrator · Source

Task execution · Guide · Symbol index

How it is used

This is the main execution path for task JSON submitted through MTCExecution. Read _execute() first: it parses the document, starts the selected tool model, groups tasks, then dispatches batches or individual actions. _execute_batch() handles combined motion planning and eligible cached replay; _execute_step() routes other operations.

The class owns task state, pause/resume services, and child action clients. Clients submit goals and service requests; the underscore methods explain the execution flow and are not a separate client API. Cache identity uses expanded tasks and resolved pose values, not just the submitted JSON text.

MTCOrchestratorServer

Top-level ROS node for multi-step execution. It coordinates MoveIt lifecycle, tools, child actions, feedback, and cached plans. It uses its own admission and fault handling rather than inheriting BaseActionServer.

Parameter

Meaning

goal_handle

MTCExecution handle carrying full_json and optional dry_run.

Returns: MTCExecution.Result with expanded total/completed counts, success/error and any retained detected pose.

Errors: Parser ValueError aborts cleanly. Handled launch/dispatch failures abort; TIMEOUT/REPLAY_TIMEOUT or cancellation during a failed unit can fault the server. Unexpected exceptions reach _execute_callback and fault it.

MTCOrchestratorServer.destroy_node()

Stop the MoveIt launch session, then destroy the ROS node.

Lifecycle · Source

destroy_node(self)

Returns: None.

Errors: An error while stopping MoveIt propagates before the node’s ROS entities are destroyed.

Side effects: Calls kill_current_process(drain=False) while rclpy is still running, which clears the model revision and stops MoveIt’s process group. Skips the discovery drain because no launch follows. Then destroys the node’s publishers, services and action endpoints.

Used by: run_server() during shutdown.

MTCOrchestratorServer._send_and_wait()

Reset the last error, attach the active model revision when the goal supports it, send the child goal and wait without spinning. Success follows result.success, not the action wrapper status.

Internal helper · Source

_send_and_wait(self, client: ActionClient, goal, name: str, timeout: float) -> bool

Parameter

Meaning

client

ActionClient for the operation.

goal

Mutable goal message.

name

Operation label used in logs/errors.

timeout

Result wait limit in seconds, excluding 5 s discovery and 10 s acceptance waits.

Returns: Child result.success on completion; False for missing revision, unavailable server, rejection, timeout or failed child result.

Errors: Acceptance/result timeouts set _faulted; result timeout requests cancellation without waiting for acknowledgement. Future/transport exceptions propagate. _last_result is replaced only after receiving a result, so earlier failures can leave it stale.

Side effects: Mutates goal revision and orchestrator error/result/fault fields, sends hardware actions and may request cancellation.
