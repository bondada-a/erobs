Demo action-server base

Share goal admission, stage execution, and result handling between the demo print and motion servers.

hello_orchestrator_py.base_action_server · Source

Examples and demos · Guide · Symbol index

How it is used

Subclass BaseActionServer for a demo operation and implement initialize_stages() to assign self._stages. That object must provide run(request) returning a boolean. run_server() owns ROS startup, spinning, and cleanup; ROS calls the admission and execution callbacks.

This teaching implementation has its own contract: it sets the busy flag when execution begins and rejects child-action cancellation by default. The production server base uses a different stage-factory and result contract.

BaseActionServer._execute_callback()

Mark busy, run stages with the goal request, populate success/error_message and succeed or abort the goal, resetting busy in finally.

Callback · Source

_execute_callback(self, goal_handle: ServerGoalHandle)

Parameter

Meaning

goal_handle

Server goal handle for the configured action type.

Returns: Configured action Result with success; failed stages use Stage execution failed and Exceptions use their message.

Errors: Catches stage/result/transition Exceptions, logs, aborts and returns failure; errors within that handler can still propagate.

Side effects: Runs stage work (including possible motion), updates action status and execution flag.

ROS action endpoint name.

action_type

Generated action class exposing Goal/Result types; Result must support success and error_message.

Errors: NotImplementedError from an unoverridden factory or RuntimeError if _stages remains None; ROS setup failures propagate.

Internal callbacks and helpers

BaseActionServer._goal_callback()

Reject a new goal when the execute callback has marked the server busy; otherwise accept it.

Callback · Source

_goal_callback(self, goal_request) -> GoalResponse

Parameter

Meaning

goal_request

Incoming action goal; contents are not validated here.

Returns: GoalResponse.REJECT when _executing is true, otherwise ACCEPT.

Errors: No explicit catch; acceptance does not reserve the busy flag until execution starts.

Side effects: Logs busy rejection only.

run_server()

Initialize ROS, construct the supplied server class and spin with interrupt handling and normal finally cleanup.

Entry point · Source

run_server(server_class, args=None)

Parameter

Meaning

server_class

Zero-argument ROS Node subclass to instantiate.

args

Optional ROS initialization argument list; None uses process arguments.

Returns: None after spin ends.

Errors: KeyboardInterrupt during spin is swallowed; constructor errors occur before the try/finally and can bypass cleanup. Other spin errors propagate after cleanup.

Side effects: Starts/spins a ROS action server, then destroys node and shuts down ROS.
