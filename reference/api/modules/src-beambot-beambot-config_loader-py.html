Beamline configuration

Load and validate the selected beamline YAML, cache its shared mapping, resolve resource paths, and translate settings for ROS launch consumers.

beambot.config_loader · Source

Setup and deployment · Guide · Symbol index

How it is used

Launch files, the orchestrator, stages, and the GUI read the beamline selected by BEAMBOT_BEAMLINE_CONFIG. load_beamline_config() validates configured gripper payloads and voltages before caching the mapping and its source path. Treat that shared mapping as read-only.

Use validate_beamline_config() to check an already parsed mapping without loading a file. It checks tool mass, center of gravity, and voltage, not the complete deployment schema. Named accessors and path/launch helpers serve individual consumers; reset the cache only when deliberately reloading configuration.

Example

With BEAMBOT_BEAMLINE_CONFIG already selecting a beamline, resolve its pose registry the same way as the orchestrator:

from beambot.config_loader import load_beamline_config, resolve_beamline_path

config, config_path = load_beamline_config()
poses_path = resolve_beamline_path(config["poses_file"], config_path)

The example reads configuration only. It assumes the selected YAML defines poses_file; do not modify the shared config mapping.

validate_beamline_config()

Collect payload and voltage problems for every configured gripper. Missing tool sections are skipped; this is not a complete configuration-schema check.

Function · Source

validate_beamline_config(config: dict) -> list[str]

Parameter

Meaning

config

Parsed configuration dictionary. Each grippers entry should be a dictionary with payload_mass, payload_cog and optional tool_voltage.

Returns: List of diagnostic strings, empty when these checks pass. Mass must be finite and positive; CoG needs finite x/y/z; voltage must compare equal to 0, 12, or 24, excluding booleans. Omitted voltage means 0 V.

Errors: Reports invalid gripper entries and checked fields in the returned list. A malformed root or truthy nonmapping grippers container can raise Python errors rather than return diagnostics. Strings and booleans are rejected for payload values.

Side effects: Does not mutate the mapping, read files, or contact hardware.

resolve_beamline_path()

Expand a configured path. Absolute inputs receive lexical normalization; relative inputs are joined to the nearest ancestor containing src, searched for at most ten levels, or to the configuration directory.

Function · Source

resolve_beamline_path(rel_or_abs: str, config_path: str) -> str

Parameter

Meaning

rel_or_abs

Configured path, absolute or relative; an empty value means no path.

config_path

Beamline YAML filename whose resolved parent anchors the search.

Returns: Resolved path string, or an empty string for an empty input. Relative-path suffixes are joined without an additional resolve call.

Errors: Filesystem/path resolution errors propagate.

Side effects: Checks ancestor directories; does not create or read the target file.

Internal callbacks and helpers

_load_beamline_config_uncached()

Read the selected YAML, require a mapping, and validate all configured gripper payloads and tool voltages before returning it.

Internal helper · Source

_load_beamline_config_uncached() -> tuple[dict, str]

Returns: Fresh (configuration_dict, absolute_path) tuple.

Errors: YAML syntax, non-mapping roots, and reported gripper validation errors become BeamlineConfigError. Validation messages are collected into one error. File-open errors and malformed container errors not handled by the validator propagate.

Side effects: Reads the environment and YAML file without populating the memoized cache.
