Shared action server

Provide shared ROS action-server startup, goal admission, and execution callbacks. A busy reservation limits each server to one goal. Child actions reject cancellation by default.

beambot.action_servers.base_action_server · Source

Task execution · Guide · Symbol index

How it is used

Start here when adding an operation server. Subclass BaseActionServer, choose the ROS node and action names in __init__(), and implement create_stages(). The returned object must provide run(goal): None means success; an error string means failure. Override _execute() when the action needs additional result fields.

run_server() supplies the ROS executor and shutdown cleanup. Goal admission and result callbacks belong to the base class; clients send ROS action goals instead of calling those callbacks directly. The action server uses the node’s default callback group; the busy flag has no separate lock.

Example

The existing MoveToActionServer supplies only the endpoint identity and stage factory. This class-definition excerpt illustrates the extension contract; the normal launch path starts the server.

class MoveToActionServer(BaseActionServer):
    def __init__(self):
        super().__init__(
            node_name="beambot_moveto_server",
            action_name="beambot_moveto",
            action_type=MoveToAction,
        )

    def create_stages(self):
        return MoveToStages(self)

The inherited _execute() calls MoveToStages.run(goal). The base callbacks turn its error string or None into the final action result. The stage implementation requires ROS/MTC libraries and installed planning configuration. Constructing the first stage initializes the shared native node; this excerpt does not start a server.

run_server()

Initialize ROS, construct an action node, attach it to MultiThreadedExecutor and spin so downstream responses can progress during blocking execution waits.

Entry point · Source

run_server(server_class, args=None)

Parameter

Meaning

server_class

Zero-argument node class to construct.

args

Optional arguments forwarded to rclpy.init.

Returns: None after shutdown.

Errors: KeyboardInterrupt and ExternalShutdownException during spin are logged; other spin errors propagate after cleanup. Failures before the try block do not receive its cleanup.

Side effects: Initializes rclpy. On spin exit, ignores further SIGINT and SIGTERM so a repeated Ctrl+C cannot interrupt cleanup, destroys the node, then calls rclpy.try_shutdown() because the signal handler may already have shut the context down. Does not explicitly call executor.shutdown.

BaseActionServer

ROS node base for one operation action. It reserves one goal at a time, runs subclass stages, finalizes the result, and releases the reservation even after an exception. Subclasses supply stages and may customize result construction.

Inherits from: Node.

BaseActionServer._execute_callback()

Run the operation, mark the action succeeded or aborted from result.success, convert execution exceptions to a failed result and always release the busy reservation.

Callback · Source

_execute_callback(self, goal_handle: ServerGoalHandle)

Parameter

Meaning

goal_handle

Accepted ROS ServerGoalHandle.

Returns: Typed action result returned by _execute, or failed result with exception text.

Errors: Catches operation/finalization exceptions, logs traceback and attempts abort; errors during exception logging/abort can still propagate.

Side effects: Executes operation stages, changes ROS goal status and clears the shared _executing flag in finally.
