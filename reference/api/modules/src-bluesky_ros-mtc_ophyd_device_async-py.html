Background Bluesky action device

Submit orchestrator tasks from Bluesky and process completion in a background ROS thread.

bluesky_ros.mtc_ophyd_device_async · Source

Clients and integrations · Guide · Symbol index

How it is used

Use MTCExecutionDeviceAsync.set() when the Bluesky plan should receive a status while ROS callbacks continue in a background thread. Initialize ROS first. The call can still wait up to ten seconds for server discovery before returning; it supports one current goal, not independent overlapping submissions.

The normal result callback completes the status and stops the thread. stop(success=False) requests cancellation while keeping result processing active. As in the blocking wrapper, canceled and aborted status labels are currently reversed, although both report failure.

A ROS node implementing the Bluesky movable interface with one background callback thread and one active execution status.

MTCExecutionDeviceAsync.set()

Submit a task and start a background thread to process its result. Server discovery can block for ten seconds before the status is returned; prior background spinning is stopped first.

Method · Source

set(self, json_path_or_string)

Parameter

Meaning

json_path_or_string

Task-file path ending in .json or JSON text accepted by the goal builder.

Returns: ActionStatus immediately after send/thread startup, or an already-failed status for server unavailability. It can block during prior-thread join, file read and discovery.

Errors: File/build/send errors propagate; server timeout becomes status exception. Does not explicitly cancel the previous goal or reset _goal_handle before replacing current status, so concurrent/repeated use is unsafe.

Side effects: May read a file, submit robot tasks, stop/start callback threads and log progress.

MTCExecutionDeviceAsync.stop()

Request cancellation when success=False; leave the task running when success=True. Keep processing callbacks until the normal action result arrives.

Method · Source

stop(self, *, success=False)

Parameter

Meaning

success

Keyword-only Boolean: False requests cancellation; True represents normal plan completion and leaves background execution active.

Returns: None; cancellation return value is ignored.

Errors: cancel_goal errors propagate.

Side effects: Logs and may send cancel request; does not shut down the node or thread directly.

MTCExecutionDeviceAsync.cancel_goal()

Send an asynchronous cancel request for the retained handle and install a logging-only completion callback.

Method · Source

cancel_goal(self)

Returns: False if no handle exists, otherwise True once the request is scheduled; does not mean cancellation was accepted.

Errors: Request creation errors propagate; completion errors are handled by cancel_done. A completed/stale retained handle is still eligible.

Side effects: Requests ROS action cancellation; relies on ongoing ROS spinning and does not itself update the status.

Internal helper · Source

Translate raw status 4 into success, 5 into a Task aborted exception with server detail, 6 into Task canceled, and other statuses into an Unknown status exception; then stop spinning.

Parameter

future

Completed action result future with status and result payload.
