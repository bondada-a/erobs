ROS and GUI bridge

Translate ROS messages, action results, and service responses into Qt signals.

mtc_gui.ros2_bridge · Source

Operator GUI · Guide · Symbol index

How it is used

The GUI startup creates ROS2Bridge and calls init_ros2(); the main window connects its signals to the panels. A ROS2Spinner services the node in a QThread. Separate daemon workers wait for action and service responses so those waits do not block the GUI. The application entry point calls shutdown() during cleanup.

execute_task() submits a complete task JSON document to beambot_execution and can cause robot motion; dry_run=True requests a plan-only preview. stop_execution() sets a flag and returns immediately. The worker skips submission if it sees that flag before sending, or waits for acceptance and requests cancellation once. After submission, it continues waiting for the server’s terminal result, even if cancellation fails.

ROS2Bridge

Own the GUI’s ROS node, subscriptions, clients, and worker coordination. Its signals carry data back to GUI-thread widgets; action and service methods communicate with the running EROBS system.

Inherits from: QObject.

ROS2Bridge.init_ros2()

Initialize rclpy and the mtc_gui_client node, register subscriptions and clients, then start a Qt spin thread.

Lifecycle · Source

init_ros2(self)

Returns: True on complete setup; False when ROS is unavailable or setup raises.

Errors: Catches Exception and emits “ROS2 init failed: …”. Partial setup is not rolled back.

Side effects: Subscribes to /color/image_color, /joint_states, /beambot/current_gripper, /beambot/execution_state, and /beambot/preview_trajectory; the last three use reliable transient-local QoS. Creates beambot_execution action and capture/pause/resume clients, optional Zivid marker client, starts QThread, and emits a log message.

ROS2Bridge.execute_task()

Submit a task JSON document to the orchestrator on a background worker.

Entry point · Source

execute_task(self, config_json: str, dry_run: bool=False)

Parameter

Meaning

config_json

Serialized task script passed verbatim to Goal.full_json; this method does not parse or validate JSON.

dry_run

Value assigned to Goal.dry_run; True requests orchestrator planning/preview without execution.

Returns: None; results arrive as action_result_received(status, error_message, completed_steps, total_steps).

Errors: Thread-start errors propagate; worker handles client/server/goal/result failures. There is no guard against concurrent invocations.

Side effects: Resets the shared stop flag and starts a worker that can dispatch robot motion unless dry_run is True.

ROS2Bridge.execute_task._run()

Submit the goal, handle stop requests, and forward the server’s terminal result.

Internal helper · Source

_run()

Returns: None.

Errors: Missing client/server or a rejected goal emits status 0 and zero counts. A stop handled before submission emits STATUS_CANCELED with zero counts and sends no goal. Server discovery waits up to 10 seconds; acceptance and result polling have no overall timeout. Cancellation-call exceptions are logged while result waiting continues; cancellation responses are not inspected. Other exceptions emit a log and status 0.

Side effects: Sends MTCExecution(full_json, dry_run), retains an accepted goal handle until result or failure, and requests cancellation at most once when stopped. A Stop request during acceptance remains pending until a handle arrives. For submitted goals, forwards the actual server status, error and completed/total counts; completion may still be successful. Clears _current_goal_handle in finally.

ROS2Spinner

Service ROS callbacks inside the QThread owned by ROS2Bridge. The bridge starts run() through the thread’s started signal and requests loop termination with stop().
