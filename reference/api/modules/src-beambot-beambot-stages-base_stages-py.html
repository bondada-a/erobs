Shared motion stages

Provide shared MTC model loading, planners, pose conversion, constraints, previews, and execution. Import reads installed planning configuration; the first stage instance initializes the shared C++ MTC node.

beambot.stages.base_stages · Source

Motion planning · Guide · Symbol index

How it is used

Operation-specific stage classes inherit BaseStages to build, plan, and execute MoveIt Task Constructor tasks. The usual flow is create_task_template() → add operation stages → load_plan_execute(). Use init_and_plan() when planning must be separated from execution, as in the orchestrator’s batch/cache path.

Planner builders and pose/constraint helpers support that flow. Blocking ROS waits require another executor thread to process responses. Import still requires ROS/MTC libraries and reads installed planning YAML. _get_mtc_node() initializes rclcpp and creates the shared beambot_mtc node only when the first stage instance is constructed.

BaseStages

Shared implementation for robot-model reuse, planner construction, task planning, previews, and execution. Subclasses provide their operation-specific run(goal) or task-composition methods; the base does not implement a generic operation. The first instance initializes the shared native node; later instances reuse it.

Send a serialized solution through a node-shared execute_task_solution action client, wait for acceptance/result and decode MoveIt success.

Method · Source

execute_solution_msg(self, sol_msg, is_replay: bool=False) -> str | None

Parameter

Meaning

sol_msg

Serialized MTC solution.

is_replay

Emit an explicit cache-replay success log when true.

Returns: None on success; descriptive error string on unavailable server, rejection, timeout, MoveIt failure or exception.

Errors: A 10 s acceptance timeout leaves acceptance unknown and does not retry. A 120 s result timeout requests cancellation and waits up to 5 s without confirming motion stopped. Exceptions become strings.

Side effects: May create/cache an action client; executes physical trajectories, requests cancellation on result timeout and logs.

BaseStages.compute_deterministic_ik()

Capture a live JointState, round seed positions to 0.01 degrees, request /compute_ik, and retain every configured arm joint from a successful solution.

Method · Source

compute_deterministic_ik(
    self,
    approach: PoseStamped,
    ik_frame: str,
) -> dict[str, float] | None

Parameter

Meaning

approach

Target PoseStamped, including its reference frame.

ik_frame

IK link name for the requested target.

Returns: Configured arm-joint name to radian-position mapping on success, otherwise None.

Errors: Missing joint state (1 s), service (2 s), response (5 s), unsuccessful code or incomplete solution return None with warnings. Service-phase exceptions are caught; initial subscription errors propagate.

Side effects: Creates/destroys a temporary joint-state subscription and IK service client. The blocking call allows 5 s for a response and requires another executor thread to process it.
