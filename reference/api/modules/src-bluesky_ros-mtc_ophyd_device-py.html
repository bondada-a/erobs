Blocking Bluesky action device

Submit orchestrator tasks through a blocking Bluesky/Ophyd device.

bluesky_ros.mtc_ophyd_device · Source

Clients and integrations · Guide · Symbol index

How it is used

Use MTCExecutionDevice.set() from a Bluesky plan to submit a task file or JSON string. Initialize ROS before constructing the device. The call processes ROS callbacks until completion and then returns its Ophyd status, so wait=False in the RunEngine does not make this wrapper asynchronous.

ActionStatus connects failed Ophyd status handling to cancellation. The wrapper currently labels canceled/aborted ROS statuses incorrectly; both still produce failed Ophyd statuses.

MTCExecutionDevice.set()

Submit a task and process ROS callbacks until its Ophyd status is done, then return the status. The call blocks; it ignores the result of its ten-second server-discovery wait.

Method · Source

set(self, json_path_or_string)

Parameter

Meaning

json_path_or_string

Task-file path ending in .json or JSON text accepted by construct_goal_message.

Returns: The ActionStatus after completion/failure; this call blocks and has no execution timeout of its own.

Errors: Input/send/callback errors are not caught here; unavailable server can leave a goal/status pending. Repeated calls overwrite shared current status/goal fields.

Side effects: Reads optional file, submits robot execution and processes ROS callbacks synchronously.

MTCExecutionDevice.cancel_goal()

Request cancellation of the retained goal and spin until its cancel future finishes or five seconds elapse.

Method · Source

cancel_goal(self)

Returns: None; no action if _goal_handle is None.

Errors: Future/spin errors propagate; cancellation acceptance/return code is not inspected, and handle may already be complete.

Side effects: Sends an action cancel request and processes ROS callbacks.

MTCExecutionDevice._result_callback()

Finish the current status for raw action status 4. For 5 use result.error_message as the exception; for 6 use Canceled; all others use Unknown status.

Callback · Source

_result_callback(self, future)

Parameter

Meaning

future

Completed get_result_async future containing status and MTCExecution result.

Returns: None; status becomes finished or exceptional.

Errors: Future/message errors propagate. Source labels 5 as aborted and 6 as canceled; standard ROS uses 5 canceled and 6 aborted, so error labeling is reversed.

Side effects: Updates Ophyd status/logs and may trigger the cancellation failure hook; retained goal handle is not cleared.

ActionStatus

Track an execution result for Ophyd and ask the associated device to cancel when the status fails.

Inherits from: DeviceStatus.
