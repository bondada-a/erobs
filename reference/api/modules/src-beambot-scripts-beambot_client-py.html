Task submission client

Submit a task JSON file to the orchestrator and report its progress and final ROS action status.

src.beambot.scripts.beambot_client · Source

Clients and integrations · Guide · Symbol index

How it is used

Use the CLI entry point to send an existing task JSON file to /beambot_execution. main() reads the file and checks JSON syntax; TaskGoalSender.send_goal() submits its full text and waits for the final action status while feedback is logged. Task validation and execution belong to the orchestrator.

This client executes the task; it is not a JSON preview tool. On Ctrl+C it requests cancellation when it has an accepted goal handle. Its exit status follows the ROS action status rather than a separate result.success check.

Entry point · Source

main()

Returns: Exits process with 0 on action success, 1 for ordinary input/action failure, or 130 after KeyboardInterrupt.

Errors: JSON/I/O errors exit 1 before ROS initialization; runtime errors can propagate after finally cleanup. A second interrupt during cancel is ignored, and ROS shutdown Exceptions are suppressed.

Side effects: Reads task file, commands orchestrator execution and prints/logs output; destroys node and shuts down ROS.

TaskGoalSender

A synchronous MTCExecution action client that retains the active goal for cancellation and logs task progress.

Inherits from: Node.

TaskGoalSender.send_goal()

Submit task JSON and wait synchronously for acceptance and the final action result. Allow ten seconds for the orchestrator to become available.

Method · Source

send_goal(self, json_content: str) -> bool

Parameter

Meaning

json_content

JSON string copied verbatim into MTCExecution.Goal.full_json; this method does not parse it.

Returns: True only for STATUS_SUCCEEDED; False for unavailable server, rejection, cancellation or other status.

Errors: Acceptance/result waits have no timeout. Unexpected future/None-result errors propagate. Result payload success is not separately inspected.

Side effects: Submits robot task execution, processes ROS callbacks and logs progress/results.
