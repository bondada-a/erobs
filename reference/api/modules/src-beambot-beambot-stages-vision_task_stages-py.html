Vision task coordination

Coordinate detector selection, target computation and motion for generic vision tasks. Detection-only requests can still perform pre-scan motion; vacuum verification is disabled.

beambot.stages.vision_task_stages · Source

Perception and mapping · Guide · Symbol index

How it is used

VisionTaskActionServer calls run() to perform optional scan positioning, detection, target computation, and motion. Detector names resolve through vision_task_detection; goal-computer names resolve through motion_target. The returned target selects Cartesian or joint execution.

Parsed path constraints reach the named scan-pose move, Cartesian approach/retreat, and joint-target positioning/contact moves. Multi-position detection uses a separate scan helper without constraints. detect_only can still involve scan motion and pre-opening, and the joint-target computer ignores it.

Related data types:

  • VisionTaskContext: Per-goal data shared with detector and goal-computer functions: the engine, goal, scan positions, optional detected pose, and error text.

VisionTaskStages

Coordinator around one VisionEngine. It exposes the action-server run(goal) contract and delegates acquisition, target calculation, and execution to separate functions.

VisionTaskStages.run()

Validate offsets and sample-ROI options, execute any scan positioning, wait the configured settle interval, resolve detector/goal-computer callables, detect and compute a motion target, then dispatch motion unless the computer supplies a detect-only/no-motion result.

Entry point · Source

run(self, goal) -> 'str | None'

Parameter

Meaning

goal

VisionTaskAction goal with detector/computer names, perception settings, pose/gripper data and target options.

Returns: None for success, detect-only or a successful no-motion target; categorized error string otherwise.

Errors: Unknown callable names become PIPELINE_CONFIG_ERROR; no detection and context errors become DETECTION_FAILED/GOAL_COMPUTE_FAILED. Detector, JSON and construction exceptions may propagate.

Side effects: Stores the goal, resets results, may move before detection-only capture, sleeps, captures/queries TF and executes arm/gripper motion. vacuum_ok is not measured.

Internal callbacks and helpers

VisionTaskStages._execute_joints()

Execute a joint-degree target, optional forward contact, and optional gripper state as separate tasks. Parsed goal constraints apply to the joint and contact moves.

Internal helper · Source

_execute_joints(self, target: JointTarget) -> 'str | None'

Parameter

Meaning

target

JointTarget with joints_deg, optional forward_distance in metres, gripper_group and terminal_state.

Returns: None on success or a stage-specific error string.

Errors: Malformed constraints JSON/data and pose/construction errors can propagate; build/planning/execution failures otherwise return a contextual error.

Side effects: Plans and executes up to three separate arm/gripper tasks.

VisionTaskStages._execute_cartesian()

Execute a bare approach through VisionEngine, or combine a PTP/LIN fallback approach, gripper action and retreat in one task. Parsed path constraints reach the bare approach and the combined approach/retreat stages.

Internal helper · Source

_execute_cartesian(self, target: CartesianTarget) -> 'str | None'

Parameter

Meaning

target

CartesianTarget containing PoseStamped, IK frame and optional gripper/retreat fields.

Returns: None on execution success; retreat or motion error string otherwise.

Errors: Malformed constraints JSON/data and stage errors propagate; missing retreat returns an error.

Side effects: Queries IK, plans and executes arm/gripper motion; bare approaches use the engine’s standalone path.

When scan_pose is present, optionally add a release action for pre_open, then execute motion to that named joint pose.
