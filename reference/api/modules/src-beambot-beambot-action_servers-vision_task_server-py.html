Vision task action server

Expose generic vision-task execution and TF reset, and warm the spincoater inference model in a daemon thread. motion_kind is inferred from the detected-pose result rather than the executed target type.

beambot.action_servers.vision_task_server · Source

Perception and mapping · Guide · Symbol index

How it is used

The orchestrator sends generic detector-and-motion requests to beambot_vision_task. This server constructs VisionTaskStages, delegates each goal, and copies detection and execution results into VisionTaskAction.Result.

create_stages() connects beamline camera settings to the coordinator. Startup also warms the spincoater model in a background thread; the TF-reset service updates the engine after tool-model changes.

VisionTaskActionServer

Concrete BaseActionServer around the generic vision coordinator. Its execution override supplies vision-specific result fields; camera, detection, and motion sequencing live in VisionTaskStages.

Inherits from: BaseActionServer.

Extension hook · Source

_execute(self, goal_handle)

Parameter

Meaning

goal_handle

Accepted VisionTaskAction handle.

Returns: VisionTaskAction.Result with optional metre XYZ and XYZW quaternion.

Errors: Stage exceptions propagate to the base wrapper.

Side effects: Runs perception/motion; fills result fields. Goal finalization belongs to BaseActionServer.
