Chat agent connection

Connect the Qt chat interface to RobotAgent on a background asyncio thread.

mtc_gui.agent_bridge · Source

Operator GUI · Guide · Symbol index

How it is used

MTCMainWindow creates AgentBridge, connects its signals, registers the task-document getter, then calls connect_agent(). The window submits messages with send_message() and calls disconnect() on closure. Agent coroutines run in the background; connected Qt slots update widgets on the GUI thread.

Queue proposals and execution requests reach the window through signals. In Run mode, execute_queue waits for the window to call notify_execution_complete(). Changing modes rebuilds the agent and resolves any pending execution wait as interrupted; it does not itself cancel the robot’s active goal.

Example

Connect an existing chat panel to an already connected agent bridge on the GUI thread. The main window uses the same signals while also coordinating queue changes and execution results.

# panel: an existing ChatPanel; bridge: its connected AgentBridge.
panel.message_submitted.connect(panel.append_user)
panel.message_submitted.connect(bridge.send_message)
bridge.response_received.connect(panel.append_assistant)
bridge.thinking_changed.connect(panel.set_thinking)
bridge.error_occurred.connect(panel.append_error)

This wiring submits chat messages. In Run mode, agent tool requests may also request queue execution through the main window’s existing handlers.

AgentBridge

Own the chat agent, its background event loop, and the Qt signals used by the main window. Public methods schedule work; the _async_* methods and local-tool dispatcher run on the agent thread.

Inherits from: QObject.

AgentBridge.connect_agent()

Start a daemon thread that connects RobotAgent and then keeps an asyncio event loop running.

Lifecycle · Source

connect_agent(self)

Returns: None; connection completion is signaled through connected(tool_count).

Errors: Thread-start failures propagate; _async_connect catches connection failures. No guard prevents duplicate starts.

Side effects: Creates and starts _thread; asynchronous work subsequently updates _loop and _agent.

AgentBridge.send_message()

Schedule a chat coroutine on the background loop when an agent is present.

Entry point · Source

send_message(self, text: str)

Parameter

Meaning

text

User message passed unchanged to RobotAgent.chat.

Returns: None; the concurrent future from scheduling is intentionally not returned.

Errors: Emits error_occurred(“Agent not connected”) if the loop or agent is missing; coroutine-scheduling errors otherwise propagate.

Side effects: Queues _async_chat, which emits thinking, tool, response, and error signals.

AgentBridge.notify_execution_complete()

Deliver the GUI execution result to a waiting execute_queue call and broadcast it through Qt.

Method · Source

notify_execution_complete(self, success: bool, error: str, completed: int, total: int)

Parameter

Meaning

success

Whether execution succeeded.

error

Execution failure detail, or an empty string for success.

completed

Count of completed task steps.

total

Total task-step count.

Returns: None.

Errors: No local exception handling; schedules set_result only when the observed pending future is unfinished.

Side effects: Uses call_soon_threadsafe to resolve the asyncio future with (success, error, completed, total); always emits execution_outcome with those four values.

AgentBridge.disconnect()

Schedule asynchronous agent cleanup on a running loop and wait at most three seconds for its thread.

Lifecycle · Source

disconnect(self)

Returns: None.

Errors: Scheduling/join errors propagate; asynchronous disconnect failures are not surfaced through an error signal here.

Side effects: Schedules _async_disconnect, joins the thread with a timeout, and clears _thread even if that timeout expires.

AgentBridge._local_dispatch()

Handle the agent’s local queue tools and route queue changes or execution requests to the window.

Callback · Source

async _local_dispatch(self, name: str, arguments: dict) -> str

Parameter

Meaning

name

Exact local tool name; unrecognized names produce an error string.

arguments

Tool argument mapping. propose_tasks uses tasks (false values become []), optional start_gripper, poses, and replace (default True); get_current_tasks and execute_queue ignore arguments.

Returns: Human-readable tool-result text, except get_current_tasks returns indented JSON containing start_gripper and tasks. execute_queue waits and returns “Execution succeeded/failed (completed/total steps)[: error]”.

Errors: propose_tasks checks only that the normalized tasks value is a list. Missing config getter, non-Run execute requests, and duplicate pending executions return explanatory strings. All Exception failures become “Local dispatch error in name: …”.

Side effects: Emits tasks_proposed(tasks, options), tasks_cleared(), or execution_requested(); calls the config getter directly; creates and clears an awaited execution future. Task-proposal signals are not awaited.
